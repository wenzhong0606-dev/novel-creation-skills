# 通用小说创作 Skill 体系

本仓库是通用创作方法、Skill模块、类型扩展及其治理规范的权威来源。架构按可复用方式设计，但当前建设以《穿越》为唯一实际应用项目。

## 当前建设状态

- **治理第一阶段：已完成基础规范与一致性收尾。** 已建立体系架构、Skill仓库与版本治理规范、ChatGPT Project—GitHub调用规范，并补齐仓库级版本、变更记录和Skill索引入口。
- **实际Skill模块：尚未开发和启用。** 当前仓库中的架构、治理与集成文档不是可直接调用的Skill；不得将规划中的能力名称或《穿越》项目内部方法V1.0记作已启用模块。
- **当前实施项目：《穿越》。** 下一阶段只从该项目真实、高频、边界清楚的任务中提取候选能力，按需开发并在项目内验证。
- **跨项目验证：未来可选。** 目前没有其他小说项目需求，不为此建立第二个项目，也不将跨项目验证作为《穿越》项目内使用或验收Skill的前置条件。只有未来出现真实复用需求时才考虑。

## 架构基线

- 总控层：识别任务、管理工作流、调度与协调Skill。
- 创作工作流层：承担创意开发、故事架构、人物设计、情绪架构、章节设计、正文创作、修订和评审等工作。
- 专项能力层：承担因果链、伏笔回收、连续性、人物一致性、独立评审等可复用任务。
- 横向扩展：小说类型扩展包为多个工作流和专项能力提供类型约束，不构成第四层。
- 人物体系设计与情绪架构设计是两个独立工作流，通过明确接口协同。

## 仓库治理原则

1. 本仓库维护通用方法、Skill、模板、评测和治理规范。
2. 单部小说的正文、世界观、人物设定、项目决策和进度资料留在该小说自己的项目仓库。
3. 小说项目通过项目级Skill清单声明实际使用的Skill及精确版本。
4. GitHub中的版本是通用Skill的权威版本；项目必须锁定实际使用的Skill版本。
5. 不将单一小说中的有效做法未经相应验证直接宣称为跨项目成熟能力。
6. 不以Skill数量、文档数量或空目录数量衡量建设进度；没有实际模块时如实保持空索引。
